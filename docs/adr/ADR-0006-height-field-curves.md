# ADR-0006：曲线剪用「高度场」，不用自由路径

- **状态**：已采纳（v0.7.0）
- **日期**：2026-10-31
- **相关**：`docs/SCISSOR_CURVES.md`、`src/geometry/cut.ts`、`src/puzzle/skill.ts`

## 背景

原有三种刀具（直线 `line`、折剪 `notch`、镂空 `hole`）只能产生直线段与超椭圆闭环。
「剪曲线」是真实剪纸的核心手法（花瓣的圆弧尖、扇贝边、S 形旋纹），也是关卡分级的最后一级。
需要在不破坏「精确切割」承诺的前提下加入曲线。

候选方案：

- **A. 自由路径**：`points: Vec2[]` + 平滑（贝塞尔/样条），按"路径 + 侧"求区域。
- **B. 高度场（本决策）**：刀口是某方向上的单值函数 `v = offset + A·sin(bends·π·t)`。
- **C. 真圆弧列表**：每段是圆弧，端点吸附纸包边界。

## 决策

采用 **B**。理由按重要性排序：

1. **可定义性**。自由路径一旦自交或回头，"剪去哪一侧"不再是单一区域，剪刀会把纸切成多块；
   模型要么允许非单连通（违反「纸 = 原纸 − 已剪」的守恒律），要么必须检测并拒绝，
   而检测本身又是一个几何算法。高度场天然不会自交，语义没有歧义。
2. **与直线严格兼容**。`A = 0` 时 `v = offset` 就是同参数直线剪，因此新原语**包含**旧原语，
   可以写"等价性测试"而不是"相似性测试"（`IoU = 1`，纸形差 < 1e-9）。
3. **误差可证**。|g''| 有闭式上界 ⇒ 弦逼近误差 ≤ `|A|·bends²·π²/(8N²)`，
   采样数由目标误差反解，界写在 UI 上并且被测过。方案 A 的平滑曲线没有这么干净的上界。
4. **参数可教**。两个数字（弯曲、弯折）就能覆盖弧线 / S / 波浪，滑块的语义能被一句话说清；
   方案 A 至少需要 4–6 个控制点，落到 UI 上就是"拖动看不见的贝塞尔手柄"。

代价与补救：

- 不支持闭合曲线 → 用 `hole`（超椭圆）表达；
- 不支持折线拐弯 → 用 `notch` 表达；
- 不是真圆弧 → 文案统一写「弧线」；同拱高下与圆弧的最大偏差为拱高的 2%–3%，
  已写入 `docs/SCISSOR_CURVES.md` §6。

## 后果

- 正向：曲线关可被"正向构造 + 同一采样器评分"，IoU 判定与直线关同样精确；
  新增 4 个曲线关，`skill` 由几何计算，文案不可能与形状不符。
- 负面：`Cut` 联合类型多一支，所有按 `kind` 分支的位置都要补（已用测试覆盖：
  页面渲染测试 + 刀型转换测试）。
- 负面：8 折下每条曲线要采样 24–98 个顶点，单次求值从 0.4 ms 升到 2.2 ms；
  仍远低于一帧预算，实时预览无需节流。

## 何时重新评估

- 若需要"剪出真正的圆弧花瓣尖"（例如与实体模板比对），考虑方案 C，并保留 B 作为近似档。
- 若需要闭合的自由轮廓，应扩展 `hole` 为任意闭合路径（此时非单连通问题同样出现，
  需要先定义"多层纸被剪穿"的语义）。
