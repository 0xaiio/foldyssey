# 交互与判定重设计（UX_REDESIGN）

> 状态：**v0.5.0 已落地**。本文既是设计说明，也是实现与验收的依据；
> 文中所有数字都来自 `src/tests/*` 的实测输出，不是估计。
> 目标不变：仍然是"折叠 → 剪切 → 展开 → 对照目标"，变的只是**怎么调**和**怎么判**。

---

## 0. 一句话结论

原来要求玩家把 IoU 顶到 **99%** 才算通关，而八折关只要把一个滑块挪**一格**（0.5°）就掉到 **98.0%**——
等于要在 360 个位置里盲猜唯一正确的那一个。这不是难度，是缺反馈。

改法三条：**容差按阶段放宽到 92/94/96%**、**随时能做一次"差在哪"诊断**、
**展开效果与目标实时对照**。100% 变成额外徽章，不再是通关条件。

---

## 1. 现状诊断（实测）

### 1.1 旧判定：99% + 对称差 2%

`score.ts` 原来是 `perfectIou = 0.99`、`perfectSym = 0.02`，而 `PuzzlePage` 只在
`verdict === 'perfect'` 时记录通关。也就是说：**IoU < 99% 一律不算过**。

### 1.2 一格滑块能掉多少（关键证据）

用每关的标准解，把某一个参数改动**恰好一个 UI 步长**（角度 0.5°、距离 0.01），
重新跑几何引擎并评分：

| 关卡 | 阶段 | 一格偏差后的最低 IoU |
|---|---|---|
| 角落初探 | 1 | 99.8% |
| 镜像之门 | 1 | 99.7% |
| 菱形奇迹 | 2 | 99.0% |
| 八角星 | 2 | **98.0%** |
| 团花 | 3 | 98.2% |
| 万象团花 | 3 | 98.1% |

**八角星的标准解是 `22.5° / 0.45 / 0.45`，滑块步长 0.5°。** 挪一格 → 98.0% → 旧判定失败。
玩家看不到"我是偏左还是偏右"，只能来回扫。这就是"难以达到 100%"的全部原因。

### 1.3 没有反馈闭环

- 折叠状态下画布只显示**纸包**，展开结果要按完「剪一刀」才出现；
- 评分只在展开后给一次，给完就结束，不能"边调边看"；
- 失败只显示"未匹配"，不告诉玩家是角度错、深度错还是方向错。

---

## 2. 设计原则

1. **容差是关卡属性，不是玩家失误。** 每个阶段有明确预算，且**一格滑块永远在预算内**（有测试）。
2. **先告诉"哪里不对"，再告诉"调哪个"。** 面积差 → 方向 → 具体滑块，三层递进。
3. **能看就不猜。** 展开结果与目标叠在一起实时更新，差异用颜色标出来。
4. **说真话。** 按钮写「剪一剪」就不是"一刀"；chip 写「1 个折剪」就不混称；达标线直接印在评分卡上。
5. **帮助有成本。** 一键微调有次数上限，第三阶段取消按钮只留方向——理解仍然值钱。

---

## 3. 交互方案：四步，不用猜

关卡页顶部固定一条**可折叠的「怎么玩 · 四步」**（默认展开），四步与界面元素一一对应：

| 步 | 标题 | 界面上对应的东西 |
|---|---|---|
| 1 | **选刀** | 切口标签页 `第 1 刀 / 第 2 刀`（单切口关卡明说"本关只有一刀"） |
| 2 | **调参** | 按类型切换的参数面板（见下表），全部是滑块，**松手即重算** |
| 3 | **看差** | 右侧「展开预览」实时比对；青=多剪、金=少剪、金色虚线=目标 |
| 4 | **落刀** | 按「剪一刀 / 剪一剪 / 剪 N 刀」→ 展开 → 本刀评分 |

参数面板按切刀类型切换（文案与用户要求逐字对齐）：

| 切刀类型 | 控件 |
|---|---|
| 直线 | 角度 / 距中心 / 剪哪侧（负侧·正侧） |
| 折剪 | 方向 / 顶点距中心 / 张口宽度 |
| 镂空 | 形状（菱形·圆形·叶形）/ 方位 / 距中心 / 半宽 / 长宽比 / 自身转角 |

**画布直接拖拽**（与滑块共用同一份模型状态）：

- 直线：拖线身平移 → 改 `offset`；拖两端圆点 → 改角度；
- 折剪：拖**顶点** → 改深度；拖**两臂** → 改方向；
- 镂空：拖圆心 → 改位置；拖轮廓 → 改转角。

## 4. 判定机制：三级阈值 + 一个徽章

### 4.1 阈值表

| 阶段 | `passIou`（通关） | `nearIou`（给方向提示） | `exactIou`（徽章） |
|---|---|---|---|
| 1 看懂折叠 | **0.92** | 0.85 | 0.995 |
| 2 对齐参数 | **0.94** | 0.88 | 0.995 |
| 3 叠加切口 | **0.96** | 0.90 | 0.995 |

判定只有四个档：

```
IoU ≥ 0.995 → exact 「完全匹配」（徽章，不影响通关）
IoU ≥ pass  → pass  「达标」（通关，可进下一关）
IoU ≥ near  → near  「接近」（显示差多少、往哪调）
否则        → miss  「未达标」
```

### 4.2 容差是怎么定的（不是拍脑袋）

约束：**一格滑块必须落在容差内**。实测一格偏差最差是八角星的 98.0%，
所以 `passIou` 必须 ≤ 0.98 才有意义；考虑到两格、三格也应该"看起来像"，
再往下取：

- 阶段 1 取 0.92：允许约 4–6 格偏移，够玩家熟悉控件；
- 阶段 2 取 0.94：允许约 2–3 格，开始要求判断；
- 阶段 3 取 0.96：允许约 1–2 格，仍不至于"差半格就白干"。

这条约束写成了自动化测试：`one slider step never fails any level` ——
**六个关卡 × 每个参数 × 正负两个方向，全部必须 `isCleared`**。
以后任何人改关卡或阈值，只要破坏这个承诺，测试立刻红。

### 4.3 评分卡说什么

- 档位文案：完全匹配（"在容差内与目标完全一致，满分"）/ 达标（"已达到本关要求，可以进下一关"）/ 接近 / 未达标；
- 三个指标：**IoU / 本关达标线 / 实得面积**（原来显示"对称差"，玩家看不懂，改成达标线）；
- 未达标时给一句**面积诊断**："还差 12.3 个点到达标线。留下的纸比目标多，说明剪少了。"
- 卡片底部印出本关达标线，并注明「完全匹配」只是额外徽章。

## 5. 降低精确控制难度：三层帮助

### 5.1 实时反馈（治"看不见"）

「剪切参数」标题右侧常驻 **`吻合 93%`**，拖动滑块时即时变化，不用先落刀。
右侧「展开预览」同步显示展开结果；阶段 1–2 默认打开「对照目标」叠加层。

### 5.2 一键诊断（治"不知道调哪个"）

「差在哪？」按钮会用**真实引擎**试算单参数扰动，挑出提升最大的一步：

- 搜索范围：当前标签页的那一刀优先；若这一步提升 < 1%，再扩到其它刀；
- 搜索粒度：滑块步长 × {1, 4, 16}（粗到细），所以距离远时一步能跨 0.16，靠近时自动变细；
- 输出：`把第 1 刀的「距中心」往 0.36 调（-0.16，约 16 格），吻合度约 +9.7%。`
- 附带「按建议调整」按钮：**阶段 1–2 限 6 次，阶段 3 不给按钮只给方向**。

### 5.3 收敛实测（从初始猜测出发，只用"照建议调"）

| 关卡 | 阶段 | 达标线 | 诊断耗时 | IoU 轨迹 | 结果 |
|---|---|---|---|---|---|
| 角落初探 | 1 | 92% | 4.1 ms | 87.4 → 93.5 → 98.3 → 99.3 → 99.8 → 100.0 | 达标 |
| 镜像之门 | 1 | 92% | 3.6 ms | 89.7 → 96.9 → 98.6 → 99.5 → 99.7 → 100.0 | 达标 |
| 菱形奇迹 | 2 | 94% | 6.9 ms | 73.3 → 93.9 → 98.0 → 99.0 → 100.0 | 达标 |
| 八角星 | 2 | 94% | 20.6 ms | 88.2 → 89.8 → 92.2 → 96.8 → 98.2 → 99.4 → 99.6 | 达标 |
| 团花 | 3 | 96% | 24.5 ms | 88.8 → 90.6 → 92.6 → 94.5 → 96.9 → 98.0 → 99.4 | 达标 |
| 万象团花 | 3 | 96% | 44.5 ms | 75.2 → 76.3 → 77.7 → 89.9 → 91.1 → 93.1 → 96.9 | 达标 |

每一行都是"**最多 6 次、从最坏的初始猜测到通关**"，写进了
`assist.test.ts > repeated nudges converge ...`。诊断是按钮触发的单次计算，
不进入拖拽帧（4–45 ms，最高的一关也不到一帧的 3 倍）。

## 6. 关卡结构：三阶段六关

| 阶段 | 关卡 | 折法 / 切口 | 这一阶段教什么 | 容错设计 |
|---|---|---|---|---|
| **1 看懂折叠** | 角落初探 | 不折 · 1 条直线 | 一刀 = 一个半平面 | 对照默认开；观察提示自动展开；达标 92%；微调 6 次 |
| | 镜像之门 | 竖折 · 1 条直线 | 折一次 = 镜像两份 | 同上 |
| **2 对齐参数** | 菱形奇迹 | 正交双折 · 1 条直线 | 四重镜像与中心孔 | 对照仍在，但观察提示要自己点开；达标 94%；微调 6 次 |
| | 八角星 | 八折 · 1 个折剪 | 剪刀拐弯才有尖角 | 同上；提示里点明"一格 = 0.5°" |
| **3 叠加切口** | 团花 | 八折 · 直线 + 折剪 | 两种切口叠加、各自复制 8 份 | 对照默认关；达标 96%；**只有方向性文字，不给一键微调** |
| | 万象团花 | 八折 · 直线 + 2 个折剪 | 三层结构、轨道概念 | 同上 |
| **4 典藏纹样** | 八方连珠 / 藻井 / 菱窗 / 六出 / 重瓣 | 八折或四折 · 5–6 刀 | 分层构图、轨道错位、折痕分叉 | 达标 96%；微调额度 8 次；档案默认折叠 |

难度递进沿三条轴同时推进，不是单纯"多一刀"：

1. **折数**：0 → 2 → 4 → 8 份；
2. **切刀类型**：直线 → 折剪 → 叠加 → 分层（5–6 刀）；
3. **帮助强度**：对照 + 自动观察提示 + 一键微调 → 对照但提示要自己开 + 一键微调 → 对照默认关 + 仅方向文字 → 档案要靠自己读、微调额度 8 次。

阶段标签直接印在关卡标题行（`LEVEL 03 · 阶段 2 · 对齐参数`），也在图案库里以 `阶段 N` 角标出现。

### 6.1 图案库：展示 → 选择 → 预览

首页的「十一个图案」是本次交互打磨的重点，布局契约如下：

| 断点 | 布局 |
|---|---|
| ≥ 1180px | 左侧 3 列卡片网格 + 右侧 300px 常驻详情面板（`position: sticky`，滚动时跟随） |
| 900–1180px | 卡片 2 列，详情面板仍在右侧 |
| ≤ 900px | 单列：卡片在上、详情在下；点卡片会 `scrollIntoView` 把详情带进视野 |
| ≤ 520px | 卡片 2 列、字号与内边距收紧，`dl` 由两栏变单栏 |

一致性约束（三处共用同一套组件与样式）：

- 卡片预览与详情预览都用 `MiniPattern`，同一个米色底、同一段内边距、同一个红；
- 卡片与详情都从 `level.cutSummary` / `FOLD_SHORT` 取文案，不各写一套；
- 选中态是 `1px` 红边 + `2px` 外发光，与全局焦点样式一致；
- 未通关/已通关只用一个角标，颜色与关卡页的「已通关」chip 相同。

留白节奏：卡片间距 14px、阶段条与网格 26px、左右两栏 24px；卡片内边距 9px，
预览内边距 8px——与详情面板的 18px/12px 形成 2:1 的层级差，避免两处"一样重"。

## 7. 「实时对照」可行性评估：可行，而且不需要降级

### 7.1 成本

一次"几何重算 + 评分"的实测耗时（八折终章关，Node 22 / Ryzen 级 CPU）：

```
engine + score per frame: 3.4 – 3.8 ms   → 约 260–290 fps 余量
```

一帧预算 16.7 ms，所以**每次拖动都重算完全来得及**，不需要节流、不需要 Web Worker、
也不需要"松手才算"。现在的实现就是 `useMemo([cuts])` 直接算，拖动时跟着更新。

### 7.2 呈现方式

- 右侧「展开预览」：`PaperStage` 以 `foldedness = 0` 渲染 `result.paper`，叠目标轮廓与差异区；
- 「对照目标」开关：阶段 1–2 默认开，阶段 3 默认关（避免直接给答案，但玩家可以自己打开）；
- 差异配色沿用全局语义：**青 = 多剪（A\T）**，**金 = 少剪（T\A）**，与评分卡的"差异覆盖"一致。

### 7.3 边界与降级

- 低端机若掉帧：几何计算本身是同步的，最坏情况是拖动发涩，不会算错；
- 如果将来加入更复杂的图案（>12 刀），再考虑 rAF 合帧或 Worker；
- 目前**没有做**"主画布直接叠差异"：折叠状态下叠展开图案会误导（两者坐标系不同），
  所以差异只出现在展开预览里。

## 10. 风险与未做的部分

| 项 | 说明 |
|---|---|
| 一键微调会被"刷" | 限 6 次、且只在阶段 1–2；理论上一路点到底也能过，但这 6 次的路径本身就是教学 |
| 诊断只搜单参数 | 两个参数同时需要调整时，会分两次提示；不搜二维组合是为了把耗时压在 50 ms 内 |
| 主画布不做实时叠加 | 折叠坐标系与展开坐标系不同，直接叠会误导；差异只在展开预览里 |
| 未做撤销/键盘微调 | 阶段 3 的精细调整仍只有滑块；如需要可加 ←/→ 单步与撤销栈 |
| 真机触控未回归 | 仍只有 Chromium + 390px 视口验证 |

## 11. 与原有目标的一致性

- 玩法没变：仍然是折叠 → 拖动一条切线/一次折剪 → 剪 → 展开 → 对照目标；
- 数学没变：目标仍由标准解**正向构造**，评分仍是**几何集**上的 IoU 与对称差，没有改用像素比对；
- 只是把"必须 100%"改成"达标即可，100% 是徽章"，并补上了**看得见的反馈**与**说得清的提示**。
