# 假设与歧义（ASSUMPTIONS）

记录方式：**问题 → 我的理解 → 采用的假设 → 依据 → 风险 → 可撤销措施**。
只记录真正影响实现的分歧点；纯技术细节不占篇幅。

---

## A-01 赛事规则无法完整核验

> **已部分推翻（v0.2.0）**：用户在第二轮明确要求"实现第 8 节 AI 创意设计师"，
> 于是运行时 AI 从"不做"改为"做，但独立可降级"。本条保留以记录当时的判断依据；
> 当前实现见 A-09。

- **问题**：活动页面需要登录，无法在这个环境里读到投稿表单的完整字段与评分细则。
- **理解**：在拿到官方表单之前，只能把"网页应用 / 公开链接 / 作品介绍 / 截图"当作确定项，
  其余（是否强制运行时 AI、社交加分细则）不得当成已知条件。
- **假设**：**不实现**运行时大模型；核心体验不依赖任何模型调用。
- **依据**：提示词 §13「未核实前不要自行假设」；若后续确认强制要求，再把 AI 提升为 Gate A。
- **风险**：若规则确实强制要求应用内调用大模型，会丢分。
- **可撤销**：`src/ai/` 未创建；`docs/AI_INTEGRATION.md` 已写好接入方案与契约，
  接入时只需新增一个服务端代理 + 一个页面入口，不影响几何与游戏。

## A-02 "一刀"的语义

- **问题**：数学上"沿一条线剪"与"剪掉半个平面"不同；前者没有面积。
- **理解**：真实剪纸中剪刀沿直线走完，留下的是**线的一侧**。
- **假设**：一刀 = 纸包平面上的一个**半平面** `{n·p < c}`，由用户选择剪去哪一侧。
- **依据**：提示词 §5.3 明确要求用半平面裁剪实现，且不能把零宽度线段相减当作孔洞。
- **风险**：若把"剪"理解为"切开但不移除"，模型完全不同（会得到裂缝而非孔洞）。
- **可撤销**：`StraightCut.removedSide` 已是一等参数，若将来要支持"切而不除"，
  增加一个 `mode: 'remove' | 'slit'` 即可，不改现有几何。

## A-03 折叠预设的坐标系

- **问题**：纸包应该放在哪个象限？
- **理解**：黄金样例 `(u,v) = (|x|,|y|)` 把纸包放在第一象限，`u,v ∈ [0,a]`。
- **假设**：`orthogonal2` 的纸包为 `[0,1]²`，四个象限通过符号翻转映进来；
  `vertical` 的纸包为 `[0,1]×[-1,1]`，`horizontal` 为 `[-1,1]×[0,1]`。
- **依据**：与提示词 §5.4 的公式逐字一致，可直接对拍。
- **风险**：与某些教材"折到左半边"的习惯相反；对外只影响动画方向，不影响结果。
- **可撤销**：只需改 `fold.ts` 中 `packet` 与 `forward` 的符号，测试会立刻暴露不一致。

## A-04 关卡标准解必须能被 UI 精确复现

- **问题**：如果标准解是 `offset = 0.4123`，滑块步长 0.01 就永远打不满分。
- **假设**：所有关卡的标准解只使用**整数角度**与**两位小数 offset**。
- **依据**：滑块 `step=1` / `step=0.01`；有测试 `canonical solutions are reproducible
  with on-screen control steps` 兜底。
- **风险**：限制了几何参数的取值密度，但 1° / 0.01 的粒度对现有 6 关足够。
- **可撤销**：放宽滑块步长即可，测试会允许更细的值。

## A-05 容差阈值

- **问题**："完全匹配"应该多严？
- **假设**：`IoU ≥ 0.99` 且 `E ≤ 0.02`。
- **依据**：滑块最小步长造成的面积误差约 `0.005`（相对面积 4），
  阈值留了 4 倍余量；而明显错误解（offset 差 0.3 以上）IoU 会掉到 0.8 以下。
- **风险**：过松会让"接近"误判为"通过"；有测试 `an obviously wrong solution is not accepted`。
- **可撤销**：阈值集中在 `DEFAULT_THRESHOLDS`，关卡可单独覆盖。

## A-06 作品数据格式

- **假设**：只存结构化参数（`schemaVersion` + 折叠预设 + 切口数组 + 配色），不存图片。
- **依据**：几何可重算，存图片会导致"图片与参数不一致"的经典 bug。
- **风险**：旧版本作品在未来几何语义变化后可能渲染不同 → 用 `schemaVersion` 拦截，
  当前只有 v1，读到非 v1 的作品会被忽略（不崩溃）。
- **可撤销**：将来加 `migrate(v1 → v2)`。

## A-07 动画的诚实边界

- **假设**：折叠动画采用"沿折痕把一侧压平再翻过去"的二维插值，端点精确、中间帧是示意。
- **依据**：提示词 §9.2 允许"二维步骤化示意"，但禁止把最终图片放大冒充仿真。
- **风险**：观感不如 3D 折叠；但不会误导用户以为做了物理仿真（About 页有说明）。
- **可撤销**：`PaperStage` 的 `patchRenderMatrix` 是唯一入口，换成三维只需替换这一层。

## A-08 未选择开源许可证

- **问题**：仓库没有 LICENSE。
- **假设**：**不擅自添加**许可证，版权归作者，等待所有者决定。
- **依据**：提示词 §15.4「不得未经用户授权擅自选择项目开源许可证」。
- **风险**：他人不能合法复用代码；比赛投稿不受影响。
- **可撤销**：由所有者选定后添加 `LICENSE` 并在 README 更新。

## A-09 运行时 AI：模型能选什么，不能选什么

- **问题**：提示词 §8.3 的示例 Schema 允许 `symmetry.order ∈ 1..8`、`motifs` 是装饰图形；
  但本程序只有四种折叠（1/2/4 重镜像）和直线切割。
- **理解**：如果照抄示例，模型可以合法返回 `order=8` 或 `type='petal'`，而程序根本画不出来——
  那就是"AI 套壳"。
- **假设**：
  1. `order` 只允许 `{1,2,4}`，与 `none/vertical/orthogonal2` 一一对应；其他值**拒绝**。
  2. `motifs` 重新定义为"五种直线切割原型"（diamond/pinwheel/chamfer/band/wedge），
     每个都有固定的 `(size, rotation) → StraightCut` 映射，写在 `motifToCut()` 里。
  3. 模型不生成路径、不生成 SVG、不生成图片。
- **依据**：§8.2 明确"模型负责主题理解、风格、配色、已实现 motif 的选择与参数建议；
  几何引擎负责实际路径、合法性、面积"。
- **风险**：表达力受限——做不出"兔子""福字"。这是几何能力边界，不是模型能力边界。
- **可撤销**：将来若加入曲线/参数化孔洞，只需扩展 `MOTIF_TYPES` 与 `motifToCut()`，
  Schema 与校验逻辑不变。

## A-10 AI 的限流值

- **假设**：5 秒间隔、每会话 12 次、30 秒超时、`max_tokens=700`。
- **依据**：keyless 通道消耗的是应用作者的额度，而这是公开链接，任何人都能点。
  12 次 × 700 token 是一个会话的保守上限；正常使用（一次生成约 3 秒）完全够。
- **风险**：真实活动中若被脚本刷，仍可能耗尽额度——客户端限流挡不住刻意绕过。
- **可撤销**：三个常量集中在 `src/ai/client.ts` 顶部；真正的兜底应放到服务端/平台配额。

## A-11 运行时 AI 的元素模型：从"motif"改为"element"

- **问题**：v0.2 的 `motifs` 是"一刀"的类型（diamond/pinwheel/chamfer/band/wedge），
  每一类都只是不同角度的直线。四条直线无法表达"花心 + 一圈花瓣 + 一圈镂空 + 齿边"。
- **理解**：提示词要求"接近民间艺术家水准"，但直线 + 四重镜像在数学上只能得到凸多边形。
  不改变元素模型，提示词写得再好也没用。
- **假设**：元素不是"一刀"，而是**一种结构**，允许一个元素展开成多刀：
  - `core` / `petal` / `hole` / `rim` / `slash` → 1 刀；
  - `sawtooth` → 8×count 刀（在楔形内等距压一排菱形孔）。
  总刀数上限 12，元素数上限 6。
- **依据**：真实剪纸的复杂度来自"结构分层"，不是"单刀形状更复杂"。
- **风险**：元素更多意味着 45° 楔形内的排布更容易互相吃掉；用 `MAX_CUTS` 与
  "会剪光就跳过"两道闸门控制。
- **可撤销**：`coerceDesign()` 同时接受旧的 `motifs` 数组并按 legacy 映射转换，旧数据不丢。

## A-12 锯齿用"边缘菱形孔"而不是"V 形缺口"

- **问题**：`notch` 的三角形底边固定在顶点外 `NOTCH_REACH=1.4` 处，
  浅齿（depth 0.08）想要 0.08 的开口需要 `width=1.4`，超出上限；
  结果浅齿必然是细针，深齿必然是长槽——看起来像"破损"，不像锯齿。
- **假设**：锯齿 = 一枚中心落在纸包边缘的菱形孔。半个菱形在纸外，
  留在纸内的一半就是三角齿；`depth` 是径向半长，`pitch/2` 是切向半宽。
- **依据**：实物剪纸的锯齿就是"从边缘剪进去再剪出来"，与边缘菱形孔等价；
  且齿深/齿距两个参数彼此独立，模型容易理解。
- **风险**：孔心正好落在边界上，属于布尔运算的退化位置；用 `clipRayToRing`
  求出精确的 rim 距离，并有"极端齿深不吞纸"的测试。
- **可撤销**：`sawtooth` 只是 `elementToCuts()` 里的一段生成逻辑，
  随时可以换成别的齿形而不影响 `Cut` 类型。
