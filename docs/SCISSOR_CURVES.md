# 剪刀能力：曲线剪与四级判定（SCISSOR_CURVES）

本文是「剪刀能剪什么、到什么程度算过关」的唯一契约。它同时回答三件事：

1. 曲线剪的**数学模型**与**精确性证明**（为什么加了曲线之后，评分依然是精确的）；
2. 「剪刀能力」**四级**的判定标准与**边界情况**（每一条都是可执行的谓词，不是文案）；
3. 曲线相关的**交互设计**（控件、手柄、读数、引导、移动端）。

代码位置：`src/geometry/cut.ts`（模型）、`src/puzzle/skill.ts`（分级）、
`src/puzzle/levels.ts`（关卡）、`src/components/PaperStage.tsx`（手柄与绘制）、
`src/components/SkillLadder.tsx`（分级条）。

## 0. 一页速览

| 级 | 能力 | 刀在纸里做什么 | 判定谓词 | 关卡数 |
|---|---|---|---|---|
| 1 | 一刀 | 直着走，不拐弯 | `cuts.length = 1` 且无折剪、无曲线 | 3 |
| 2 | 两刀 | 两条直线，各自独立 | `cuts.length ≥ 2`，无折剪、无曲线 | 2 |
| 3 | 拐弯 | 在纸里改变一次方向（V 形折剪） | 存在 `notch`，无曲线 | 7 |
| 4 | 曲线 | 在纸里**连续**转向（弧线 / S 形 / 波浪） | 存在 `curve` 且 `\|amplitude\| > 0.01` | 4 |

四条判据都作用在**关卡的正向构造切口**上，由 `skillOf(cuts)` 计算；界面上的徽章、
关卡列表、分级条读的是同一个函数，所以文案不可能与几何不一致。

## 1. 模型：曲线是一条「高度场」，不是一条自由路径

### 1.1 定义

```ts
type CurveCut = {
  kind: 'curve';
  angle: number;        // 法线方向（与直线剪同一个约定）
  offset: number;       // 弦到纸包中心的有符号距离
  amplitude: number;    // 有符号弯曲量，0 = 直线
  bends: 1 | 2 | 3;     // 半波数：弧线 / S 形 / 波浪
  removedSide: 'negative' | 'positive';
};
```

在纸包的局部正交标架 `(u, v)` 中（`v` 就是 `angle` 方向的法线，`u` 与之垂直），刀口是

```
v = offset + A · sin( bends · π · t ),     t ∈ [0, 1] 沿纸包在 u 方向的跨度
```

剪去的一侧沿用直线的语义：`positive` 剪 `v > 上式` 的一侧，`negative` 剪另一侧。
`bends` 是**半波数**，因此刀口的拐点数恰为 `bends − 1`：

| `bends` | 图形 | 拐点 | 界面标签 |
|---|---|---|---|
| 1 | 单侧鼓起（弧线） | 0 | 弧线 |
| 2 | 一个 S | 1 | S 形 |
| 3 | 两个 S 相连 | 2 | 波浪 |

### 1.2 为什么不用「任意路径」

任意折线/贝塞尔路径可以自交、可以回头、可以绕圈。一旦允许回头，"剪去哪一侧"就不再是
一个区域：剪刀回头会把纸切成两块以上，属于**多连通**结果，超出「移除一侧」的定义，
也让「纸 = 原纸 − 已剪」这条守恒律失效。

把刀口限制成 u 的单值函数（高度场）之后：

- **不会自交**：每个 u 只有一个 v，环「图 + 远处的墙」必定是简单多边形；
- **剪去一侧有定义**：`{ v > g(u) }` 是半平面的直接推广，仍是单连通区域；
- **与直线严格兼容**：`A = 0` 时就是 `v = offset`，即同参数的直线剪。

这是本项目的取舍：**放弃「任意曲线」，换来「每条曲线都可被精确定义、验证、评分」**。
需要闭合曲线时用「镂空」（`hole`），需要拐弯折线时用「折剪」（`notch`）。

### 1.3 波长为什么按纸包归一

`t` 的跨度取纸包在 `u` 方向的投影 `[u_min, u_max]`，而不是世界坐标的固定长度。
理由是可预期性：`bends = 2` 必须意味着「手里这张纸上一个完整的 S」，否则同一个滑块位置
在 `vertical`（纸包宽 1）和 `radial8`（楔形跨度约 1.3）上会给出完全不同的图案，
关卡就无法用「调到 0.66」这样的说明来教。

## 2. 精确性：把曲线采样成折线，但误差有闭式上界

### 2.1 采样数

```ts
N = clamp( ceil( π · bends · sqrt(|A| / (8 · ε)) ), 24, 192 )   // 取偶
ε = CURVE_CHORD_TOLERANCE = 1.2 × 10⁻³   （纸宽为 2）
```

`A = 0` 时取 `N = 2`（此时曲线就是直线，采样没有意义）。

### 2.2 误差上界

由插值误差的标准估计：弦逼近的偏差不超过 `|g''| · h² / 8`，而

```
|g''| ≤ |A| · (bends · π / L)² ,   h = L / N
⇒  |g − 折线| ≤ |A| · bends² · π² / (8 N²)
```

`curveChordError()` 返回的就是这个上界，界面上的「折线误差」读数直接显示它。

| 关卡 | `\|A\|` | `bends` | `N` | 误差上界 |
|---|---|---|---|---|
| 波边 `scallop` | 0.18 | 1 | 24 | 3.9 × 10⁻⁴ |
| 旋风 `swirl` | 0.16 | 2 | 26 | 1.2 × 10⁻³ |
| 葫芦 `jar` | 0.24 | 3 | 48 | 1.2 × 10⁻³ |
| 花窗 `lattice` | 0.16 | 1 | 24 | 3.4 × 10⁻⁴ |
| 滑块极限（`\|A\|=1, bends=3`） | 1.00 | 3 | 98 | 1.2 × 10⁻³ |

测试 `the sampled polyline stays inside the certified chord bound` 用 20 倍密采样实测
每个点到折线的距离，要求 `实测 ≤ 1.35 × 上界`——即上界不是"写上去的"，是被测过的。

### 2.3 为什么这不影响评分

目标区域由**同一套采样器**正向构造，玩家的作答也走同一条路径。所以

```
IoU(作答, 目标) 比较的是两个同源折线区域，
近似误差在两边完全相同地出现，不会造成系统性偏差。
```

`the polygonised area converges to the refined area` 另外验证：把采样加密 1000 倍后，
面积相对变化 < 2 × 10⁻³——即"我们叫做曲线的那块区域"确实是那条曲线。

### 2.4 守恒律与等价性（都是测试，不是声明）

| 不变量 | 测试 | 断言 |
|---|---|---|
| `A = 0` 时等于同参数直线 | `amplitude 0 is exactly the straight cut…` | `IoU = 1`（1e-10）、纸形差 < 1e-9 |
| `纸 + 已剪 = 原纸` | `paper + removed is still the whole sheet` | 四种折法 × 三种 `bends` 都 `≈ 4` |
| 纸不超出原纸 | 同上 | `area(paper) ≤ 4 + 1e-9` |
| 八折下图案不变 | `the 8-fold pattern is invariant under the symmetry group` | 90° 旋转与镜像下逐点一致 |
| 同一输入同一输出 | 既有 `byte-identical geometry` | 路径字符串一致 |
| 性能 | `one curve evaluation stays fast enough…` | ≤ 60 ms/次（实测 2.2 ms） |

## 3. 四级判定：可执行的谓词

`strokeStats(cuts)` 把每一刀翻译成"手的动作"，`skillOf` 再取最高的一级：

```ts
line  → corners 0,  inflections 0, curved false
notch → corners 1,  inflections 0, curved false
curve → corners 0,  inflections bends-1, curved = |A| > 0.01
hole  → closed += 1                       // 单独一条轴，不参与升级
```

优先级：`曲线 > 拐弯 > 两刀 > 一刀`。**刀法比刀数重要**：一条曲线高于两条直线。

| 级 | 判定标准 | 通过条件（判定机制） | 边界情况 |
|---|---|---|---|
| **一刀** | 恰好一条直线切口，剪去一个半平面 | IoU ≥ 92%（阶段 1） | 切线压在折痕上：两侧纸各复制一次，缺口宽度为零但轮廓仍在，仍算「一刀」并提示「切在折痕上」；切线完全在纸包外：面积不变，**不计为一刀**（`warnings` 报告"没有碰到"）|
| **两刀** | 同一纸包上两条直线，各自独立 | IoU ≥ 94% | 两刀完全重合：第二条不产生新面积，仍记两刀，诊断提示重复；两刀相交：后一刀只剪剩余的纸，**顺序不影响形状**（面积可交换，有测试）；其中一刀落空：仍按两刀计，但提示该刀无效果 |
| **拐弯** | 至少一条切口在纸包内改变方向（V 形折剪） | IoU ≥ 94–96% | 折剪顶点落在纸包中心：八扇区共用同一顶点，缺口退化为锥形，仍是有效图案；两臂落在同一条折痕上：视为拐弯而非曲线（刀只转了一次）；张口为 0：`normalizeCut` 拒绝，计入 `warnings` |
| **曲线** | 至少一条切口在纸包内连续转向，`\|amplitude\| > 0.01` | IoU ≥ 96% | `amplitude = 0`：退化为直线，按前三级的规则判定（有等价性测试）；`\|amplitude\| > 1.5`：截断到 1.5；`bends` 非整数：就近取整到 1/2/3；整条曲线落在纸包外：警告、纸形不变；曲线把纸包剪光：警告"整叠纸都会被剪掉"；**自交 / 回头 / 闭合**：不在模型内（见 §1.2），闭合需求用「镂空」表达 |

**「镂空」是另一条轴，不是第五级。** 它在 `strokeStats` 里记 `closed`，界面作为徽章与
`cutSummary` 出现（例如"1 条直线 + 3 个镂空"），因为「戳一个闭环」与「剪一条开口路径」
是两种不同的操作，不构成同一个能力序列上的先后关系。

### 3.1 每一格的容差余量（实测）

"一格滑块不会判失败"是阶段化容差的承诺（见 `docs/UX_REDESIGN.md`）。曲线关的实测最差邻居：

| 关卡 | 达标线 | 一格滑块后最差 IoU | 余量 |
|---|---|---|---|
| 波边 `scallop` | 96% | 97.4% | +1.4 |
| 旋风 `swirl` | 96% | 98.3% | +2.3 |
| 葫芦 `jar` | 96% | 98.0% | +2.0 |
| 花窗 `lattice` | 96% | 97.2% | +1.2 |

最紧的直线关是「六出」97.2%（同为 96% 线、+1.2），所以曲线关**不需要**更宽的容差：
它拿到的是与阶段 4 相同的 96%，而不是"曲线更难所以放宽"。

## 5. 交互设计

### 5.1 控件

| 控件 | 范围 / 步长 | 作用 | 为什么这样设计 |
|---|---|---|---|
| 角度 | 0–179.5°，0.5° | 法线方向 | 与直线剪同名同义，玩家不必重新学一套坐标系 |
| 距中心 | −1.6–1.6，0.01 | 弦的位置 | 同上；决定了"这条弧离纸心多远" |
| 弯曲 | −1–1，0.01 | 有符号弯曲量 | 中间值 0 是**直线**，滑块本身承担了"从直到弯"的过渡；下方三档刻度写「内凹 / 0=直线 / 外凸」 |
| 弯折 | 弧线 / S 形 / 波浪 | 半波数 1/2/3 | 三档对应"刀不拐弯 / 转向一次 / 连续起伏"三种手感 |
| 剪去哪一侧 | 法向负侧 / 法向正侧 | 移除哪一半 | 与直线剪一致 |

读数条（`role="status"`）：`切口长` / `拐点` / `曲边占比` / `折线误差`。
四个数字都是当前几何的真实测量，不是常量：拖动时同步变化。

### 5.2 画布手柄（直接操作）

| 手柄 | 形状 | 拖动的效果 |
|---|---|---|
| 两端 | 圆点 | 绕纸心旋转刀口 |
| 线身中点 | 圆点 | 平移（沿法线移动弦） |
| 弯曲 | **菱形** | 沿法线拉/推，直接改 `amplitude`；手柄按下后始终跟着手指 |

辅助图形：

- **虚线**连接刀口两端 = 弦。弯曲量就是刀口偏离这条虚线的距离，不需要额外解释；
- **空心小圆点**标在拐点上（`bends − 1` 个）。S 形与波浪的"拐了几次"因此可见；
- 刀口本身用 `clipPath` 裁到纸包内，永远画在纸内，不会出现"线飘到纸外"的错觉。

### 5.3 引导

- **分级条**（页面顶部）显示四级、当前级、每级关卡数，以及「本关考什么」一句话；
  折叠区里给出四级的判定与边界（就是 §3 的内容）。
- **操作说明第二格**按当前刀型给出不同的控件说明；曲线关写「三个滑块 + 弯折三档」。
- **拖动说明**单独一行写清三种刀型各自的拖法。
- 关卡列表每行显示 `刀数 · 刀法`，与分级条同源。

### 5.4 移动端

- 画布 `touch-action: pan-y`：竖向滑动仍然可以滚页面；手柄单独 `touch-action: none`，
  抓住手柄后手势完全交给拖拽。
- 触屏只在**手柄**上触发拖拽（`pointerType !== 'mouse'` 时不响应空白处点击），
  鼠标保留"点哪剪哪"。这样手机上不会被画布"吃掉"滚动。
- 分级条在 620 px 以下隐藏关卡数、缩小图标，仍保持一行四级。

### 5.5 反馈一致性

| 事件 | 反馈 |
|---|---|
| 弯曲从 0 变成非 0 | 读数从「直」变为「内凹 / 外凸」，菱形手柄出现 |
| 弯折切换 | 拐点圆点的数量立刻变化（0 / 1 / 2） |
| 拖动中 | 右侧预览与 IoU 同步刷新（实测一次求值 2.2 ms，无需节流） |
| 落刀后 | 展开动画 → 评分卡 → 差异覆盖 |
| 曲线整条在纸外 | 画布上不画刀口，参数面板下方提示"没有碰到纸包" |

## 6. 已知限制（不得越界宣称）

1. **曲线不是真圆弧**，是正弦弧。同拱高下两者最大偏差约为拱高的 2%–3%；
   选择正弦是为了让 `bends = 1/2/3` 共用一套采样与误差界。文案一律写「弧线」而非「圆弧」。
2. **不支持自交、回头、闭环的开口剪**（见 §1.2）。需要闭环请用「镂空」。
3. **采样是折线**，误差上界 1.2 × 10⁻³（纸宽 2），界面显示实测值；导出 SVG 也是折线。
4. **正方形最多折出 8 重**，六重对称只能用八折近似（「六出」关已如实标注）。
5. 曲线在**不同折法下形状不同**（波长按纸包归一），同一个"弯曲 0.2"在 `vertical` 与
   `radial8` 上不是同一条曲线。这是刻意的选择，见 §1.3。
