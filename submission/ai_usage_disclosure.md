# AI 使用披露（AI Usage Disclosure）

> 分两部分：**开发期**用了 AI 辅助写代码；**运行期**网页里真实接入了大模型，
> 但它只生成受约束的设计参数，不画图。两者不能合并成一句"本应用使用了 AI"。

## 一、开发期

| 项 | 内容 |
|---|---|
| 使用方式 | 在 WorkBuddy 中以"需求规格 → 代码 → 测试 → 发布"的方式辅助开发 |
| 涉及的产物 | TypeScript 组件与几何模块初稿、测试用例、文档草稿、本目录的参赛材料 |
| 人工把关 | 几何定义、黄金样例、容差阈值、能力边界与"不做"的清单由人确定并逐条核对 |
| 可追溯 | 全部代码在 Git 历史中；测试与浏览器验证可重跑（见 `TEST_REPORT.md`） |

## 二、运行期（公开网页）

| 项 | 内容 |
|---|---|
| 是否调用大模型 | **是**，仅「AI 灵感」页，且只由用户点击「生成设计」触发 |
| 模型提供方 | WorkBuddy 云服务的 LLM 通道（keyless），实测模型 `glm-5.3-flash` |
| 是否需要用户 API Key | 不需要；前端只有可公开的 `endpoint` 与 `publishableKey` |
| 发送了什么 | 只有用户在输入框里写的那一句主题描述（≤ 120 字） |
| 没有发送什么 | 作品、关卡进度、浏览记录、任何身份信息 |
| 模型输出 | 一段 JSON 设计参数（主题/风格/对称阶数/配色/1–3 个 motif/标题/一句说明） |
| 谁来画图 | 本机的几何引擎。模型不生成图片、SVG 或代码 |
| 输出如何使用 | 先 `JSON.parse`，再用 `zod` 严格校验；越界或未知字段直接拒绝，不执行、不拼 HTML |
| 失败时 | 显示原因 + 重试 + 改用预设模板；核心玩法完全不受影响 |
| 数据留存 | 生成结果只在当前页面与浏览器内存里；保存作品时也只存参数到 localStorage |

## 三、模型能做什么、不能做什么

**能**：理解"喜庆的八瓣红色窗花"这类主题，挑一种折叠阶数、挑 1–3 种切割原型、
给出尺寸/角度/配色与命名。

**不能**：生成任意图案（只有五种直线切割原型）、生成图片、声称某个复杂图案
"一刀就能剪出"、编造学术来源。这些限制写在系统指令里，也在代码里硬性校验
（`src/ai/schema.ts`）。

## 四、素材与生成内容

- 没有 AI 生成的图片、视频或音频进入作品。
- 所有图案由 `src/geometry/` 的确定性代码计算，同一参数永远得到同一结果。
- 截图与录屏均为真实运行页面（`submission/screenshots/`、`tools/shots/`）。

## 五、准确表述

- ✅ 「应用内置 AI 灵感设计师：用一句话描述主题，模型给出受约束的设计参数，几何引擎画出真实图案。」
- ✅ 「开发过程由 AI 辅助。」
- ❌ 「AI 直接生成窗花图片。」
- ❌ 「AI 可以把任意图案变成一刀剪纸。」
