# AI 使用披露（AI Usage Disclosure）

> 结论：**开发期使用 AI 辅助；作品运行时没有任何大模型调用。** 这两件事必须分开看。

## 一、开发期

| 项 | 内容 |
|---|---|
| 使用方式 | 在 WorkBuddy 中以"需求规格 → 代码 → 测试 → 发布"的方式辅助开发 |
| 涉及的产物 | TypeScript 组件与几何模块初稿、测试用例、文档草稿、本目录的参赛材料 |
| 人工把关 | 几何定义、黄金样例、容差阈值、能力边界与"不做"的清单由人确定并逐条核对 |
| 可追溯 | 全部代码提交在 Git 历史中；测试与浏览器验证可重跑（见 `TEST_REPORT.md`） |

## 二、运行时（公开网页）

| 项 | 内容 |
|---|---|
| 是否调用大模型 | **否** |
| 网络请求 | 无（页面不加载第三方字体/图片/统计脚本，断网可完整游玩） |
| 是否需要用户提供 API Key | 不需要 |
| 用户数据 | 作品与进度只写在浏览器 localStorage，不上传 |
| 失败降级 | 不适用（没有可失败的外部依赖） |

## 三、为什么没有做运行时 AI

1. 赛事原始页面需要登录才能读取，无法确认"作品内是否强制调用大模型"。
2. 本项目的核心是可验证的几何；AI 只能做参数建议，不能替几何引擎决定形状。
3. 时间窗口极短，接入需要服务端代理、限流、Schema 校验与失败降级，
   会挤占"数学正确 + 手机可用 + 线上可访问"的预算。

如果后续接入，契约与安全要求已写在 `docs/AI_INTEGRATION.md`：
模型只输出受约束的 JSON 参数（枚举 + 数值范围），由几何引擎生成实际路径；
密钥只在服务端；失败时保留全部核心功能。

## 四、素材与生成内容

- 无 AI 生成的图片、视频或音频进入作品。
- 所有图案由 `src/geometry/` 的确定性代码计算，同一输入得到同一结果。
- 截图与录屏均为真实运行页面（见 `submission/screenshots/` 与 `tools/shots/`）。

## 五、需要更正的说法

如果任何介绍里出现「本应用内置 AI 生成窗花」，那是不准确的。
准确表述是：**本应用用计算几何生成剪纸图案；开发过程由 AI 辅助。**
